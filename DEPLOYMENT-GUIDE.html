1项目概览

厦门培训网是一个面向厦门本地教育培训市场的信息服务平台，聚合培训机构、课程、资讯等内容，为用户提供一站式培训信息检索服务，同时为培训机构提供展示与获客渠道，通过广告位实现商业化变现。

4本地开发环境搭建

4.1 克隆项目

git clone <仓库地址> xiamenpeixun
cd xiamenpeixun

4.2 安装依赖

npm install
Prisma 7 注意事项
Prisma 7 不再默认将客户端生成到 node_modules/@prisma/client，而是在 schema.prisma 中通过 output = "../src/generated/prisma" 指定输出路径。npm install 后需手动执行 npx prisma generate 生成客户端代码。

4.3 配置环境变量

项目根目录已有 .env 和 .env.local 两个文件：

  • .env — Prisma CLI 读取的数据库连接地址（提交到 Git）
  • .env.local — Next.js 运行时读取的密钥和 URL（不提交到 Git）

首次搭建需修改 .env.local 中的 NEXTAUTH_SECRET，使用以下命令生成新密钥：

# 生成随机密钥
openssl rand -hex 32

# 将输出值填入 .env.local
NEXTAUTH_SECRET=<生成的密钥>
NEXTAUTH_URL=http://localhost:3000

4.4 生成 Prisma 客户端并初始化数据库

# 生成 Prisma 客户端代码
npx prisma generate

# 创建 SQLite 数据库文件并应用 schema
npx prisma db push

# 播种初始数据（通过 API 路由）
# 先启动开发服务器
npm run dev

# 然后在浏览器访问：
# http://localhost:3000/api/seed

4.5 启动开发服务器

npm run dev

浏览器访问 http://localhost:3000 即可。

6数据库管理

6.1 Prisma 常用命令

# 生成 Prisma 客户端代码（修改 schema.prisma 后执行）
npx prisma generate

# 将 schema 变更推送到数据库（开发环境快速同步）
npx prisma db push

# 创建数据库迁移文件（生产环境推荐）
npx prisma migrate dev --name <迁移名称>

# 应用迁移到生产数据库
npx prisma migrate deploy

# 打开 Prisma Studio 可视化管理界面
npx prisma studio

# 重置数据库（危险！删除所有数据后重新创建）
npx prisma migrate reset
禁止在生产环境使用 db push
npx prisma db push 会直接修改数据库结构且不生成迁移文件，可能导致数据丢失。生产环境必须使用 npx prisma migrate deploy。

6.2 Prisma Studio 数据管理

npx prisma studio

默认在 http://localhost:5555 打开可视化界面，可直接浏览和编辑所有数据表。

6.3 播种数据

项目通过 /api/seed API 路由执行播种，包含：

  • 7 个课程分类（中小学辅导、艺术兴趣、体育运动、职业技能、学历提升、考证培训、语言留学）
  • 12 家培训机构（覆盖厦门6个区）
  • 20 门课程
  • 6 篇文章
  • 1 个测试用户账号
# 确保开发服务器正在运行
npm run dev

# 访问播种接口
curl http://localhost:3000/api/seed
# 或在浏览器中打开 http://localhost:3000/api/seed
安全提醒
播种接口 /api/seed 没有鉴权保护，生产环境部署前必须移除或禁用此路由（删除 src/app/api/seed/route.ts 或添加环境变量判断）。

6.4 迁移到 PostgreSQL（生产推荐）

当数据量增长或需要多实例部署时，建议迁移到 PostgreSQL：

  1. 修改 prisma/schema.prisma 中 datasource provider 为 postgresql
  2. 修改 .env 中 DATABASE_URL 为 PostgreSQL 连接字符串
  3. 执行 npx prisma migrate dev --name init-postgresql 创建初始迁移
  4. 使用 npx prisma db push 或编写数据迁移脚本将 SQLite 数据导入 PostgreSQL
  5. 更新 src/lib/prisma.ts，移除 LibSQL 适配器，改用标准 PrismaClient 初始化
// 迁移到 PostgreSQL 后的 prisma.ts
import { PrismaClient } from "@/generated/prisma/client";

const globalForPrisma = globalThis as unknown as {
  prisma: PrismaClient | undefined;
};

export const prisma = globalForPrisma.prisma ?? new PrismaClient();

if (process.env.NODE_ENV !== "production") globalForPrisma.prisma = prisma;

7生产部署 — Vercel（推荐）

Vercel 是 Next.js 的官方托管平台，零配置部署，自动 CI/CD、HTTPS、CDN 和边缘缓存。

7.1 部署步骤

  1. 将代码推送到 GitHub / GitLab / Bitbucket 仓库
  2. 登录 vercel.com，点击 "Add New Project"
  3. 导入 Git 仓库，Vercel 自动识别 Next.js 项目
  4. 在 "Environment Variables" 中配置： 
    DATABASE_URL=file:./dev.db
NEXTAUTH_SECRET=<openssl rand -hex 32 生成的密钥>
NEXTAUTH_URL=https://www.xiamenpeixun.com
  5. Build Command 保持默认 next build（Vercel 自动检测）
  6. 点击 "Deploy"，等待构建完成（约 2-3 分钟）
  7. 部署成功后，在 Settings → Functions 中确认 Serverless Functions 正常
  8. 在 Settings → Domains 中添加自定义域名

7.2 Vercel 数据库方案

方案说明适用场景
Vercel PostgresVercel 托管的 PostgreSQL，与项目同区域推荐，免费额度够初期使用
Turso (LibSQL)边缘分布式 SQLite，兼容当前适配器无需改代码，免费额度大
外部 PostgreSQL自建或云托管 PG（Supabase / Neon / RDS）中大型站点
Turso 无缝迁移
如果选择 Turso 作为生产数据库，只需将 DATABASE_URL 改为 Turso 提供的 libsql:// 连接字符串并添加 DATABASE_AUTH_TOKEN 环境变量即可，无需修改任何代码（项目已使用 @prisma/adapter-libsql）。

7.3 Vercel 自动部署

配置完成后，每次推送到 main 分支会自动触发生产部署，推送到其他分支会生成 Preview Deployment。可在 Vercel Dashboard → Deployments 中查看构建日志和回滚。

7.4 构建钩子（可选）

如需在构建后执行 Prisma 迁移，在 package.json 中添加 postbuild 脚本：

"scripts": {
  "build": "prisma generate && next build",
  "postinstall": "prisma generate"
}

8.2 Docker 部署

创建 Dockerfile：

FROM node:20-alpine AS base

# 安装依赖
FROM base AS deps
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci

# 构建
FROM base AS builder
WORKDIR /app
COPY --from=deps /app/node_modules ./node_modules
COPY . .
RUN npx prisma generate
RUN npm run build

# 生产镜像
FROM base AS runner
WORKDIR /app
ENV NODE_ENV=production

RUN addgroup --system --gid 1001 nodejs
RUN adduser --system --uid 1001 nextjs

COPY --from=builder /app/public ./public
COPY --from=builder --chown=nextjs:nodejs /app/.next/standalone ./
COPY --from=builder --chown=nextjs:nodejs /app/.next/static ./.next/static
COPY --from=builder /app/prisma ./prisma
COPY --from=builder /app/src/generated ./src/generated

USER nextjs
EXPOSE 3000
ENV PORT=3000
ENV HOSTNAME="0.0.0.0"

CMD ["node", "server.js"]

构建并运行：

# 构建镜像
docker build -t xiamenpeixun:latest .

# 运行容器
docker run -d \
  --name xiamenpeixun \
  -p 3000:3000 \
  -v /var/www/xiamenpeixun-data:/app/prisma \

9Nginx 反向代理配置

VPS 部署时需配置 Nginx 将 80/443 端口流量转发到 Next.js 的 3000 端口。

9.1 安装 Nginx

sudo apt-get install -y nginx

9.2 站点配置

创建 /etc/nginx/sites-available/xiamenpeixun：

server {
    listen 80;
    server_name www.xiamenpeixun.com xiamenpeixun.com;

    # 重定向到 HTTPS
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name www.xiamenpeixun.com xiamenpeixun.com;

    # SSL 证书路径（见第10节）
    ssl_certificate /etc/letsencrypt/live/www.xiamenpeixun.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/www.xiamenpeixun.com/privkey.pem;

    # SSL 优化
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers ECDHE-RSA-AES256-GCM-SHA512:DHE-RSA-AES256-GCM-SHA512:ECDHE-RSA-AES256-GCM-SHA384:DHE-RSA-AES256-GCM-SHA384;
    ssl_prefer_server_ciphers on;
    ssl_session_cache shared:SSL:10m;
    ssl_session_timeout 1d;

    # 安全头
    add_header Strict-Transport-Security "max-age=63072000; includeSubDomains; preload" always;
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header Referrer-Policy "strict-origin-when-cross-origin" always;

    # 反向代理到 Next.js
    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;
    }

    # Next.js 静态资源缓存
    location /_next/static/ {
        proxy_pass http://127.0.0.1:3000;
        proxy_cache_valid 200 1y;
        add_header Cache-Control "public, immutable";
    }

    # 上传文件大小限制
    client_max_body_size 10M;
}

9.3 启用站点

# 创建软链接
sudo ln -s /etc/nginx/sites-available/xiamenpeixun /etc/nginx/sites-enabled/

# 测试配置语法
sudo nginx -t

# 重载 Nginx
sudo systemctl reload nginx

13数据备份与恢复

13.1 SQLite 备份（当前方案）

# 手动备份
cp /var/www/xiamenpeixun/prisma/dev.db /backup/dev-$(date +%Y%m%d-%H%M%S).db

# 自动备份脚本（添加到 crontab）
#!/bin/bash
BACKUP_DIR="/backup/xiamenpeixun"
DATE=$(date +%Y%m%d)
mkdir -p $BACKUP_DIR
cp /var/www/xiamenpeixun/prisma/dev.db $BACKUP_DIR/dev-$DATE.db
# 保留最近 30 天备份
find $BACKUP_DIR -name "dev-*.db" -mtime +30 -delete

# crontab 每天凌晨 3 点执行
# 0 3 * * * /backup/backup.sh

13.2 PostgreSQL 备份

# 手动备份
pg_dump -U <user> -d <dbname> -F c -f /backup/xiamenpeixun-$(date +%Y%m%d).dump

# 恢复
pg_restore -U <user> -d <dbname> -c /backup/xiamenpeixun-20260701.dump

13.3 恢复流程

  1. 停止应用服务：pm2 stop xiamenpeixun
  2. 备份当前损坏的数据库文件（以防万一）
  3. 用备份文件覆盖：cp /backup/dev-20260701.db /var/www/xiamenpeixun/prisma/dev.db
  4. 执行 npx prisma generate 确保客户端同步
  5. 重启服务：pm2 start xiamenpeixun
  6. 验证数据完整性
备份策略建议
  • 每日自动备份，保留 30 天
  • 每周手动下载到本地或云存储（异地备份）
  • 每月进行一次恢复演练，确保备份可用
  • 重大版本更新前必须手动备份

18.2 Next.js 版本升级注意事项

大版本升级风险
Next.js 大版本升级（如 14 → 15）可能引入 Breaking Changes，必须在本地充分测试后再部署。建议创建新分支进行升级测试。

18.3 Prisma 版本升级注意事项

Prisma 7 与 Prisma 6 差异显著，升级时需注意：

  • Prisma 7 需要显式指定 output 路径
  • Prisma 7 使用 prisma-client provider 而非 prisma-client-js
  • Prisma 7 生成 ESM 客户端，旧版 CJS 脚本需适配
  • SQLite 适配器导入名为 PrismaLibSql（小写 q），不是 PrismaLibSQL
  • 升级后需重新执行 npx prisma generate

19故障排查指南

19.1 常见问题速查表

现象可能原因解决方案
启动报错：Cannot find module '@/generated/prisma/client' Prisma 客户端未生成 执行 npx prisma generate
启动报错：PrismaLibSql is not a constructor 适配器导入名错误 确认导入名为 PrismaLibSql（小写 q），非 PrismaLibSQL

页面 500 错误 数据库连接失败 检查 DATABASE_URL 是否正确，SQLite 文件是否存在且有权限

useSearchParams 报错 缺少 Suspense 边界 将使用 useSearchParams 的组件包裹在 <Suspense> 中

502 Bad Gateway Next.js 进程未运行 pm2 restart xiamenpeixun；检查 pm2 logs
页面加载很慢 数据库查询未命中索引或数据量过大 检查查询条件是否命中索引；添加分页
sitemap.xml 访问 500 数据库查询失败 检查 Prisma 连接是否正常；查看服务端日志

19.2 日志排查流程

  1. 查看应用日志：pm2 logs xiamenpeixun --lines 50
  2. 查看 Nginx 错误日志：sudo tail -50 /var/log/nginx/error.log
  3. 查看 Nginx 访问日志（检查状态码）：sudo tail -50 /var/log/nginx/access.log
  4. 检查服务状态：pm2 status / sudo systemctl status nginx
  5. 检查磁盘空间：df -h（磁盘满会导致 SQLite 写入失败）
  6. 检查内存：free -m（内存不足会导致进程被 kill）

19.3 紧急恢复流程

网站完全不可用时
  1. 确认服务器是否可达：ping <域名>
  2. 确认 Nginx 运行：sudo systemctl status nginx，如停止则 sudo systemctl start nginx
  3. 确认 Next.js 进程：pm2 status，如停止则 pm2 restart xiamenpeixun
  4. 如果数据库损坏：使用最近的备份恢复（见第13节）
  5. 如果代码有问题：回滚到上一个 Git commit 并重新构建
  6. 恢复后验证：访问首页、登录、课程列表等核心功能
